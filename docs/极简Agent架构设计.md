# 极简 Agent 架构设计

- 日期：2026-11-07
- 状态：独立服务第一版开发中；以下区分已确认边界与建议设计，不表示所有验收项已完成。

## 1. 目标与已确认边界

最小完整闭环：用户绑定飞书账号，在私聊发送消息，系统定位用户及会话，加载长期记忆和 Skill，执行共享 Agent，保存原始对话并回复，后台压缩更新长期记忆。

用户已确认：共享 Agent 定义；首个渠道为飞书；第一版仅私聊；自动压缩形成长期记忆并持久化；每轮保存原始用户消息和助手回复，压缩不修改或删除原始消息。

已确认部署为独立应用，位于仓库外 `/Users/xujia/Code/data-agent`（独立项目，不随本仓库提交），使用独立多用户登录、Web AI 工作台及独立数据库。第一版不接入原平台菜单、SSO、业务数据库和工具授权；平台跳转与 REST 工具连接留待后续。原平台内置 Data Agent 保持原有职责，不迁移现有聊天。

第一版完整路径：用户登录独立账号 → Web 对话或绑定飞书私聊 → 持久化输入与执行记录 → 共享 Agent 定义调用模型及可信工具 → 保存原始回复并展示或投递 → 后台更新跨会话长期记忆。账号通过管理员命令创建，服务不开放自助注册。

## 2. 当前仓库与复用边界

现有 `backend/agent/runtime/data_agent.py` 的 DataAgent 通过独立 AgentRunState 承载单次运行；`backend/app/modules/agent_chat/services.py` 负责聊天持久化、加载记忆和调用 Runtime。当前会话摘要和工具事实见 [ADR-046](adr/agent-access/ADR-046-agent-session-memory.md)，尚不具备用户级跨会话长期记忆，互斥仅限进程内。

若扩展当前平台，应复用用户、认证、会话、工具授权和 Runtime，扩展现有持久化职责，不另建平行 Agent 或授权体系。现有清空会话会删除消息与摘要；本方案的“压缩不删除原文”不修改现有显式清空功能，新增长期记忆后的清空语义须另行确认。

若选择独立应用，平台作为外部工具提供方，通过现有 REST 工具接口接入；独立应用不直接读取平台业务数据库。运行框架选型随部署边界确定，当前不预设更换 SDK。

## 3. 职责与依赖

```text
飞书接入 → 身份绑定 → 会话与执行服务 → Agent Runtime → 已授权工具
                              ↓              ↑
                         消息、Run       Skill 与记忆快照
                              ↓
                         记忆压缩任务
```

| 职责 | 拥有的规则与数据 |
| --- | --- |
| 飞书接入 | 校验事件来源、识别私聊、规范化消息、回复投递 |
| 身份绑定 | 飞书身份归属、绑定码消费、解绑 |
| 会话与执行 | 会话归属、消息顺序、Run 状态、执行准入、持久化 |
| Agent Runtime | 模型与工具循环；不持有 ORM 或跨用户可变状态 |
| Skill 加载 | 部署目录发现、读取说明、声明依赖；不授予权限 |
| 记忆处理 | 提炼压缩、来源追踪、游标、版本与更新冲突 |

以上是职责，不要求每项都建立服务类、注册中心或独立部署。

共享定义包含基础指令、模型配置、工具与 Skill 定义版本。每次运行独立创建 user_id、session_id、run_id、当前授权、记忆版本及回复目标；这些值由服务端解析，模型不能指定其他用户身份。记录执行所用定义及 Skill 版本，更新定义不改变已经运行中的快照。

## 4. 飞书绑定与会话

第一版以独立服务的已认证本地账号为身份根：登录后获取短时一次性绑定码，在飞书私聊机器人提交，服务端用可信事件中的身份原子消费绑定码并绑定。绑定码只存摘要，限制有效期、次数并避免日志输出；已有绑定冲突不得静默改绑。

外部身份唯一键包含渠道、应用、租户和渠道用户标识，避免不同应用或租户碰撞。每个请求重新检查绑定有效性与用户权限；机器人凭证不进入模型、消息或记忆。

建议首次私聊创建会话，后续进入该私聊当前会话；允许新建或切换本人会话。Web 与飞书可主动关联同一会话，不自动合并全部历史；回复仅投递来源渠道，不广播。绑定身份不等于授权读取任意会话。

首版业务输入建议仅文本；群聊与其他消息类型给出明确不支持结果，不触发 Agent。飞书具体接收方式、鉴权字段、事件响应及接口契约在接入实施前以官方文档核验，不在此草案猜测。

## 5. 原始记录与长期记忆

原始聊天是完整记录，长期记忆是由原始对话自动提炼、合并和压缩的派生数据。不存在“压缩后用摘要替换原文”的步骤。会话摘要仅用于同一会话续聊；用户长期记忆用于跨会话理解，两者不可混用。

建议长期记忆分为：稳定用户信息与偏好、持续目标与决定。临时任务细节进入会话摘要；助手猜测和历史工具结果不得变成已确认的用户事实或当前业务数据。所有记忆保留来源消息引用及时间；冲突未解决时保留来源差异，明确更正可替代旧事实。

加载顺序：基础指令 → 当前权限与 Skill 简介 → 相关长期记忆 → 当前会话摘要与近期完整轮次 → 当前输入。记忆以参考数据注入，不能成为授权依据或覆盖系统指令。需要早期细节时通过受用户归属校验的历史查询获取原文。

为记忆、历史、工具结果和最终回复分别预留上下文预算；超过预算时优先选择相关条目、压缩旧轮次或限制工具返回，不截断当前用户问题。精确 token 预算通过模型上下文上限与实测确定。

### 5.1 自动更新与恢复

1. 回复落库时标记该会话有待处理消息，不依赖内存回调作为唯一任务凭据。
2. 后台读取有界的完整轮次、该会话已处理位置、用户记忆 revision。
3. 模型生成结构化记忆候选，校验来源、范围、长度及凭证过滤后合并压缩。
4. 同一事务提交记忆新版本与会话处理游标；revision 不一致则重新读取合并，不覆盖其他会话的新记忆。
5. 失败保留旧版本及游标，记录错误并退避重试；下一次聊天可以读取旧记忆，不阻塞回复。

不同会话使用各自游标，不能以用户全局最大消息 ID 代表已完成范围。压缩任务具备租约与版本检查，重复任务不会重复写入或越过未处理消息。为每个用户序列化记忆更新可进一步降低冲突，但不能只依赖进程内锁。

记忆更新允许最终一致：刚结束的其他会话内容可能尚未进入长期记忆；当前会话最近消息始终从原始记录加载。展示“已记住”应以记忆写入成功为准。

建议提供记忆查看、修正、遗忘能力。遗忘需增加来源排除或截止范围，避免从旧聊天重建；它不自动删除原始聊天。删除原文、清空会话及其与长期记忆的联动属于独立产品规则，实施前明确，不由压缩任务决定。

## 6. 逻辑数据模型

下表是概念模型；若扩展平台，应映射并扩展现有表，不按表名新建重复数据。

| 对象 | 关键字段与约束 |
| --- | --- |
| User | 用户身份，优先复用现有用户 |
| ChannelIdentity | 用户、渠道、应用、租户、外部账号、绑定状态；有效外部身份唯一 |
| BindingCode | 摘要、用户、到期时间、消费状态；原子消费 |
| Session | 用户、会话摘要、摘要游标、长期记忆提取游标 |
| ChannelSession | 外部私聊、当前内部会话；会话必须属于绑定用户 |
| Message | 会话、序号、角色、正文、来源事件、Run、时间；来源事件去重 |
| Run | 输入消息、定义版本、Skill 版本、记忆版本、状态、租约、错误分类 |
| Delivery | Run、回复目标、分片序号、状态、渠道回执、重试时间 |
| UserMemory | 用户、结构化条目、来源引用、revision、压缩版本、更新时间 |
| MemoryExclusion | 用户、来源范围或遗忘对象；防止旧数据重新提取 |
| UserSkill | 用户、Skill 名称及启用状态；不包含工具授权 |

记忆初期可以每用户一份有界结构化文档，不引入向量数据库。原始消息及工具审计分别保存；未完成的助手流式片段不能伪装成完整成功回复。

## 7. 执行、投递与事务

建议接入事务原子保存输入与 queued Run，提交后确认接收事件。重复事件返回已有接收结果，不重复执行。后台直接扫描数据库待执行记录，避免数据库与额外消息队列双写；若扩展平台需评估复用既有调度机制，不能另建同职责执行框架。

Run 状态：`queued → running → succeeded / failed / cancelled / interrupted`。Delivery 状态：`pending → sending → delivered / failed / unknown`。结果与待投递内容在同一事务保存，外部发送不放在数据库事务中。

同一会话按持久化序号串行，不同会话并发；通过数据库原子认领和租约保证跨进程互斥。运行中续租，状态落库检查租约代次，过期执行者不得覆盖新状态。外部工具写操作还需独立幂等保护，数据库租约不能撤销已经发出的外部请求。

Agent 成功但回复失败，仅重试投递；超时不确定是否发送成功时进入 unknown，对账或人工重试，不宣称恰好一次。长回复拆成有序分片，每片保存投递记录。解绑后停止新请求，发送前重新核验绑定。

进程崩溃导致执行中断时标记 interrupted，不自动重放整个工具循环；只有确认无副作用或具备幂等保障才允许重试。取消是协作行为，不能保证撤回已完成的外部操作。记忆任务失败不改变已成功的 Run。

## 8. Skill 与权限

第一版建议仅加载管理员部署的可信 Skill 目录，启动发现名称、说明与版本，运行时按需读取完整 SKILL.md。读取资源时限制路径在 Skill 根目录，不执行任意上传脚本。

安装、用户启用和工具授权分别检查。Skill 声明依赖不产生权限；工具执行前实时校验用户、资源和参数范围。记忆与旧工具结果只供理解，不能绕过当前数据授权。外部服务凭证由服务端凭证存储解析，不能通过 Skill 正文携带。

## 9. 用户可见入口与内部动作

建议沿用现有会话及消息入口，新增以下能力；具体 URL 和字段在部署边界确定后冻结：

- 创建绑定码、查看绑定、解绑本人飞书账号。
- 私聊发送文本、创建或切换本人会话、停止当前执行。
- 查询执行状态与投递结果，区分执行失败和发送失败。
- 查看、修正、遗忘本人长期记忆。
- 列出与启用系统已部署 Skill。

服务端内部仅需接收消息、执行下一 Run、投递回复、更新记忆四条完整用例，不暴露要求调用方按顺序拼装的底层动作。

## 10. 验收与实施顺序

先完成单用户单会话的飞书绑定、文本输入、一个真实 Skill、原始对话保存、回复和自动长期记忆闭环，再补充跨会话、并发与恢复。

验收覆盖：

- 两个用户共享定义但无法读取彼此会话、记忆、凭证；权限撤销即时影响工具。
- 新会话可利用旧会话压缩出的长期记忆；原始消息内容及数量不因压缩改变。
- 同一用户两会话并发完成不会覆盖或遗漏记忆；失败不推进游标，重试不重复合并。
- 重复飞书事件只生成一次输入和 Run；同会话跨进程执行保持顺序。
- Agent 成功而投递失败不会再次执行工具；未知发送结果明确可见。
- 绑定码过期、重复使用、身份冲突、群聊、非法消息均有明确结果。
- Skill 越权、路径越界、记忆提示注入不能突破权限。
- 解绑、取消、工作进程崩溃与记忆任务失败可观察、可恢复。

## 11. 实施前决策

已确定独立应用、独立多用户登录，第一版不集成原数据平台。为保留原始记录，首版不提供删除或清空会话入口；记忆遗忘只排除派生记忆与旧来源，不删除原文。Web 中显式关联飞书当前会话，回复仅返回来源渠道。

实施顺序：

1. FastAPI 同源 API、独立 Web 工作台、管理员创建账号与服务端登录会话。
2. SQLite 独立持久化、显式初始化迁移、输入去重、持久化 Run、跨进程认领与取消恢复。
3. OpenAI 兼容模型接口、可信 Skill 快照、受用户归属约束的历史检索与有限统计计算工具。
4. 后台长期记忆提取、来源检查、版本冲突处理与遗忘来源排除。
5. 飞书事件验证、一次性绑定、私聊接收与持久化回复投递。
6. 安全及并发测试、Web 构建和浏览器验证、独立运行与部署说明。

模型与飞书真实联调需部署者提供自身凭证；未完成外部联调前不得宣称生产验收通过。SQLite 使用本机磁盘，不跨主机共享数据库文件；进程重启不自动重放中断的 Agent 工具循环。
